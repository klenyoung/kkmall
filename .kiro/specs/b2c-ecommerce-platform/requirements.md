# KKMall 小电商平台 MVP 需求摘要

## 1. 产品目标

构建一个面向普通消费者的单商家自营实物商品商城，第一版通过响应式 Web 跑通“浏览商品 -> 加入购物车 -> 下单 -> 模拟支付 -> 商家发货 -> 用户查看订单”的核心闭环。

## 2. 用户端需求

1. 用户可以通过手机号 + 模拟验证码登录。
2. 用户可以访问固定首页模块，浏览分类入口、推荐商品和商品列表。
3. 用户可以查看商品详情，选择 SKU，查看价格和库存。
4. 用户可以将商品加入购物车，修改数量或删除商品。
5. 用户可以在结算页填写或选择收货地址。
6. 系统需要在结算页展示商品金额、运费、满 99 包邮提示和应付金额。
7. 用户可以提交订单并完成模拟支付。
8. 用户可以查看订单列表、订单详情和发货物流信息。

## 3. 后台需求

1. 商家可以新增、编辑、上下架商品。
2. 商家可以维护分类、SKU、价格、库存和图片。
3. 商家可以查看订单列表和订单详情。
4. 商家可以按订单状态筛选订单。
5. 商家可以对已支付待发货订单录入物流公司和物流单号。
6. 发货后订单状态变更为已发货。

## 4. 核心业务规则

1. 运费规则：商品金额满 99 元包邮，未满 99 元收取 10 元固定运费。
2. 库存规则：提交订单前校验库存，模拟支付成功后扣减库存。
3. 支付规则：第一版仅支持模拟支付，不接微信支付或支付宝。
4. 短信规则：第一版仅支持模拟验证码，不接真实短信服务。
5. 售后规则：第一版不做系统内退款、退货、换货申请，售后走线下客服。
6. 首页规则：第一版使用固定首页模块，不做后台装修。

## 5. 不在 MVP 范围

- 多商家入驻。
- 真实支付和支付回调。
- 真实短信验证码。
- 优惠券、满减、积分等营销系统。
- 商品评价、内容社区、AI 推荐。
- 系统售后、退款、退货、换货。
- 首页可视化装修。
- 财务报表、仓储盘点、复杂物流轨迹接口。
