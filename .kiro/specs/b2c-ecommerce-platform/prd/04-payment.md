# 04 交易域 PRD

## 1. 功能概述

交易域负责平台所有资金流转，包括支付发起、支付回调处理、退款申请与处理、财务对账。安全性和幂等性是本域的核心设计原则。

## 3. 业务流程

### 3.1 支付流程

```
用户在支付页选择支付方式
    ↓
系统校验订单状态（必须为待付款）
    ↓
订单状态变更为：支付中（幂等锁，防止重复支付）
    ↓
调用支付宝/微信支付 SDK 创建支付单
    ↓
返回支付参数（二维码/跳转链接）给前端
    ↓
用户完成支付
    ↓
支付平台异步回调（Webhook）
    ├── 验证签名（RSA2）
    ├── 幂等校验（支付单是否已处理）
    ├── 金额校验（回调金额 = 支付单金额）
    └── 更新支付单状态为：成功
    ↓
发布 payment.success 事件（MQ）
    ├── 订单域：订单状态 支付中 → 待发货
    └── 业财域：生成财务流水
    ↓
前端轮询支付结果（每2秒，最多30次）
    ↓
支付成功 → 跳转订单详情页
```

### 3.2 退款流程

```
客服审核通过售后工单
    ↓
系统创建退款单（状态：待退款）
    ↓
退款单状态变更为：退款中（幂等锁）
    ↓
调用支付宝/微信退款 API
    ↓
支付平台异步回调
    ├── 退款成功
    │       ↓
    │   退款单状态：已退款
    │   发布 payment.refunded 事件
    │       ├── 订单域：订单状态 退款中 → 已退款
    │       ├── 仓储域：释放/回补库存
    │       └── 业财域：生成退款流水
    │   发送退款成功通知（短信+站内信）
    │
    └── 退款失败
            ↓
        退款单状态：退款失败
        发布 payment.refund_failed 事件
        订单域：订单状态 退款中 → 售后中
        通知客服人工处理
```

### 3.3 支付幂等保障机制

```
幂等键设计：idempotency_key = orderNo + "_" + paymentMethod

场景1：用户重复点击支付按钮
    → 查询幂等键，支付单已存在且状态为 PAYING
    → 直接返回已有支付参数，不重复创建

场景2：支付回调重复推送
    → 查询支付单状态，已为 SUCCESS
    → 直接返回 success，不重复处理

场景3：退款重复请求
    → 查询退款单状态，已为 APPLYING 或 SUCCESS
    → 直接返回，不重复发起退款
```

## 4. 支付安全要求

| 安全项 | 要求 |
|--------|------|
| 签名验证 | 所有支付回调必须验证 RSA2 签名，验签失败直接拒绝 |
| 金额校验 | 回调金额必须与支付单金额一致，不一致时告警并拒绝 |
| HTTPS | 所有支付相关接口强制 HTTPS |
| 幂等处理 | 支付和退款操作必须幂等，防止重复扣款/退款 |
| 敏感信息 | 支付密钥不得出现在日志中 |
| 防重放 | 回调接口校验 timestamp，超过5分钟的回调拒绝处理 |

## 5. 界面要求

### 5.1 支付页
- 展示订单号、商品摘要、实付金额
- 支付方式选择（支付宝/微信支付）
- 倒计时（剩余支付时间）
- 支付宝：展示二维码或跳转按钮
- 微信：展示二维码（PC）或调起微信（移动端）
- 支付结果轮询期间展示 loading 状态

### 5.2 支付结果页
- 成功：展示订单号、金额、"查看订单"按钮
- 失败：展示失败原因、"重新支付"和"取消订单"按钮
- 处理中：展示"支付处理中，请稍候"，提供手动刷新按钮
