# KKMall 商品详情页精简天猫版需求文档

## 1. 背景与问题

当前 KKMall 商品详情页只覆盖基础商品图、标题、SKU、价格、库存和加入购物车，信息密度偏低。用户参考天猫商品详情页后，明确希望补齐评价、参数、图文详情、本店推荐、看了又看、SKU 图片/标签、配送服务、优惠信息、销量和数量选择等模块。

本需求目标不是完整复刻天猫，而是在 KKMall 单商家自营商城现有能力上，做一版“精简天猫版”商品详情页，让用户能在详情页完成“了解商品 -> 判断权益 -> 选择规格 -> 查看评价/参数/详情 -> 加购或购买”的主要决策过程。

## 2. 目标与成功标准

1. 商品详情页首屏具备清晰的购买决策信息，包括商品图、标题、副标题、品牌、价格、销量、优惠、服务承诺、SKU、库存、数量和购买入口。
2. 商品详情页下方具备内容承接区，包括用户评价、参数信息、图文详情、本店推荐和看了又看。
3. 后台具备基础维护能力，运营可以维护商品详情页所需的主要展示信息。
4. 后端接口返回真实结构化数据，不依赖前端硬编码拼接核心业务内容。
5. 缺少评价、推荐、详情图文、参数等数据时，页面能优雅降级，不影响 SKU 选择和加入购物车。

## 3. 目标用户与场景

### 3.1 目标用户

- 普通买家：查看商品、比较规格、确认价格权益、加入购物车或购买。
- 运营人员：维护商品卖点、参数、图文详情、SKU 图片、服务文案和推荐内容。
- 商家客服：通过详情页服务说明减少重复咨询。

### 3.2 使用场景

1. 用户从首页、商品列表或推荐位进入商品详情页，先查看主图、标题、价格、销量和优惠。
2. 用户根据 SKU 文案、图片、库存状态选择规格，并调整购买数量。
3. 用户查看配送、运费、服务承诺，判断是否放心购买。
4. 用户查看评价、参数和图文详情，确认商品质量、规格和使用场景。
5. 用户对当前商品犹豫时，通过本店推荐或看了又看继续浏览其他商品。

## 4. 功能需求

### 4.1 首屏商品决策区

1. 展示商品主图和缩略图，支持多图切换。
2. 图片缺失或加载失败时展示统一商品占位，不出现破图。
3. 展示品牌或自营标识、标题、副标题、销量和卖点标签。
4. 展示当前售价、划线价或优惠前价格。
5. 展示轻量优惠信息，例如满 99 包邮、立减、限时优惠、自营保障等。
6. 展示配送与服务承诺，例如运费说明、发货说明、售后客服、正品保障。

### 4.2 SKU 与数量

1. SKU 支持文本规格展示，优先复用现有 `specName/specValue/specs` 能力。
2. SKU 支持图片展示，用于颜色、款式、套装等需要视觉区分的规格。
3. SKU 需要有默认态、选中态、不可选态和售罄态。
4. 用户选择不同 SKU 后，价格、划线价、库存、主图或规格图片可联动变化。
5. 数量默认值为 1，不能小于 1，不能超过当前 SKU 可售库存。
6. 未选择可购买 SKU、商品下架、SKU 禁用或库存不足时，购买按钮不可用并给出明确提示。

### 4.3 购买操作

1. 保留加入购物车能力。
2. 新增立即购买入口，第一期可复用现有结算链路：将当前 SKU 和数量加入购物车后进入结算，或由设计阶段确认更合适的直达结算方式。
3. 加入购物车成功后默认留在当前详情页并提示成功，不强制跳转购物车。
4. 未登录用户触发购买动作时进入登录流程，登录后回到原商品详情页。
5. 移动端需要提供底部固定购买栏，方便用户随时加购或购买。

### 4.4 评价模块

1. 展示评价摘要，包括评价数量、好评率或评分、评价标签。
2. 展示若干条代表性评价，包含用户昵称、评价时间、SKU 信息、评价内容和评价图片。
3. 暂无评价时展示友好空态。
4. 第一阶段不建设完整评价发布、追评、审核和举报流程，评价数据可使用种子数据或后台维护的轻量数据。

### 4.5 参数信息模块

1. 展示商品参数，包含品牌、分类、型号、材质、尺寸、重量、产地、适用场景等。
2. 参数以结构化表格或列表展示，便于用户扫描。
3. 参数为空时隐藏参数内容或展示轻量空态，不展示空表格。
4. 参数内容应与 SKU 信息不冲突。

### 4.6 图文详情模块

1. 展示商品图文详情，承载商品卖点、细节图、使用场景、使用说明和注意事项。
2. 第一阶段可基于现有 `detailHtml` 或后台维护的详情文本/图片实现。
3. 图文详情为空时展示空态或隐藏模块。
4. 图文详情不应影响首屏购买区加载和交互。

### 4.7 推荐模块

1. 展示本店推荐商品，推荐项包含图片、标题和价格。
2. 展示看了又看商品，推荐项包含图片、标题和价格。
3. 点击推荐商品进入对应商品详情页。
4. 推荐列表不展示当前商品。
5. 第一阶段不做个性化推荐算法，默认使用同类目商品、热销商品或后台配置作为推荐来源。

### 4.8 后台维护诉求

1. 后台商品编辑需要支持维护详情页所需的基础内容：卖点、参数、图文详情、SKU 图片、服务说明、优惠文案。
2. 评价和推荐若第一阶段使用种子或轻量配置，需要提供可维护或可初始化的数据来源。
3. 未维护扩展内容的商品仍应能正常保存和上架。

## 5. 非功能需求

1. 页面风格延续 KKMall 当前天猫参考方向，但不复制天猫品牌素材。
2. 桌面端采用“左侧商品图 + 右侧购买信息 + 下方内容 Tabs/分区”的结构。
3. 移动端采用纵向详情结构，并提供底部固定购买栏。
4. 商品基础信息和购买操作优先加载，评价、推荐、图文详情加载失败不阻塞购买链路。
5. 价格、优惠、服务承诺不能虚假展示，应与当前系统实际能力一致。
6. 前台、后台和 API 文案主要使用中文；代码标识、API 路径和类型名保持英文。

## 6. 范围外

1. 不建设完整营销系统，不做优惠券领取、复杂满减、会员价、积分等能力。
2. 不建设完整评价生产链路，不做订单完成后评价、追评、审核、举报。
3. 不建设真实个性化推荐算法。
4. 不建设多商家店铺体系，“本店推荐”按 KKMall 单商家自营理解。
5. 不建设完整售后系统，不新增退款、退货、换货申请。
6. 不改变现有支付、库存扣减、订单状态流转主流程。

## 7. 验收标准

1. 进入上架商品详情页，可以看到主图、缩略图、标题、品牌、副标题、价格、销量、优惠、服务承诺、SKU、库存、数量和购买入口。
2. 多图商品可以切换图片；无图或破图商品展示统一占位。
3. SKU 支持文字和图片展示，选中、禁用、售罄状态清晰。
4. 切换 SKU 后，价格、库存和可购买状态正确变化。
5. 数量选择不能小于 1，不能超过当前 SKU 库存。
6. 加入购物车成功后停留在详情页并提示成功。
7. 立即购买入口可进入后续结算流程。
8. 未登录用户点击购买动作时进入登录流程，登录后回到当前商品详情页。
9. 页面展示评价摘要和代表性评价；无评价时展示友好空态。
10. 页面展示参数信息和图文详情；数据为空时不出现异常空白或报错。
11. 页面展示本店推荐和看了又看商品，且不包含当前商品。
12. 后台可以维护详情页所需基础内容，保存后前台能展示。
13. 桌面端和移动端主要视口下布局不遮挡、不溢出，移动端底部购买栏可用。

## 8. 需求澄清记录

1. 用户选择第一期方向为 `A 精简天猫版`。
2. 第一阶段目标是增强前台详情页，同时补齐必要的后端接口、数据模型和后台基础维护能力。
3. 评价第一阶段不做完整用户评价闭环，可使用种子数据、后台轻量维护或空态降级。
4. 推荐第一阶段不做个性化算法，可使用同类目商品、热销商品或后台配置。
5. 优惠第一阶段仅做轻量展示，不引入完整营销系统。
6. 商品服务承诺必须基于 KKMall 当前可履约能力，避免展示无法兑现的承诺。
