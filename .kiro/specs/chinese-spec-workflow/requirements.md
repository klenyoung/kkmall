# 中文 Spec 工作流规范需求

## 背景与问题

项目已引入 spec-first 协作规则，但原 `agents.md` 使用英文编写，且没有明确的中文优先 Hook。后续需求沟通和文档编写可能出现中英文混用，降低团队阅读效率。

## 目标与成功标准

目标：

- 将根目录 `agents.md` 改为中文编写。
- 增加中文优先 Hook，约束后续回答和文档编写主要使用中文。
- 保留 spec-first、需求澄清、设计澄清和实现前门禁规则。

成功标准：

- `agents.md` 主体内容为中文。
- 存在中文优先 Hook 文档。
- 后续新需求默认以中文进行沟通、澄清、spec 编写和交付说明。

## 目标用户与使用场景

目标用户：

- 项目维护者。
- 后续参与 KKMall 开发的 Agent。

使用场景：

- 用户提出新需求。
- Agent 编写 `.kiro/specs/**` 文档。
- Agent 更新 `docs/**` 或 `agents.md`。
- Agent 完成实现后输出交付说明。

## 功能需求

- `agents.md` 必须使用中文描述协作规范。
- 规范必须保留 spec-first 流程。
- 规范必须明确“需求澄清”和“设计澄清”为强制环节。
- 规范必须明确每个需求至少包含 `requirements.md`、`design.md`、`tasks.md`。
- 规范必须明确实现前门禁。
- 新增 Hook，规定后续回答和文档编写主要语言为中文。

## 非功能需求

- 不改业务代码。
- 不改变现有 API。
- 不影响前后端运行。
- 文档必须清晰、可执行、便于后续 Agent 遵守。

## 范围外事项

- 不实现自动化脚本强制检查语言。
- 不翻译已有历史文档。
- 不修改业务功能。

## 风险、约束与假设

- 假设 Hook 可通过 `.kiro/steering` 长期规则表达。
- 假设用户允许代码标识符、API 字段、命令和错误码继续保持英文。
- 风险是未来 Agent 忽略文档，因此需要在 `agents.md` 和 Hook 中同时声明中文优先规则。

## 验收标准

- 根目录存在 `agents.md`。
- 存在 `.kiro/steering/chinese-language-hook.md`。
- `agents.md` 包含“中文”“需求澄清”“设计澄清”“requirements.md”“design.md”“tasks.md”“实现前门禁”。
- Hook 文档包含“中文优先”“inclusion: always”。

## 需求澄清记录

- 用户要求：“文档改为用中文编写”。
- 用户要求：“添加一个 hook，后续的回答和文档编写主要语言使用中文”。
- 本次需求只处理协作规范和 Hook 文档，不改业务代码。
